# QualiZ セキュリティ対策メモ

ハッカー・不正利用・コンテンツ盗用（AIによる複製を含む）への対策を、実態に即してまとめた運用メモです。
「今すぐやる」→「継続的に守る」→「事業が伸びたら着手」の順に整理しています。

最終確認：秘密鍵の混入なし／`.env`等は未追跡／アプリ埋め込みキーは公開用（`appl_`）で安全（2026年7月時点）

---

## ✅ 現状の良い点（すでに守れている）

- **秘密情報はリポジトリに入っていない**（APIシークレット・秘密鍵なし）。`.gitignore` で `*.p8` `*.p12` `.env*.local` を除外済み。
- アプリに埋め込む RevenueCat キーは **公開用キー（`appl_`/`goog_`）**。これはクライアントに載せて安全な種類。本当のシークレット（RevenueCat Secret API Key、App Store Connect API Key `.p8`）は **EAS サーバー / RevenueCat ダッシュボード側だけ** にあり、アプリには入らない。
- 課金は **RevenueCat がサーバー側でレシート検証** するため、脱獄端末の偽装購入はほぼブロックされる。
- 個人情報をほぼ収集しない（学習進捗は端末内 AsyncStorage のみ）。→ 万一の漏洩でも被害が小さい設計。

## 🔴 今すぐやる（無料・最優先）

### 1. 全アカウントに2段階認証（2FA）
配信経路（ビルド・提出）の乗っ取りを防ぐ最重要対策。以下すべてで有効化する：

- [ ] **Apple ID**（App Store Connect / 開発者アカウント）— iPhoneの設定 → 名前 → サインインとセキュリティ → 2ファクタ認証
- [ ] **GitHub**（`jayson-aman`）— Settings → Password and authentication → Two-factor authentication（認証アプリ推奨）
- [ ] **Expo / EAS**（`masaya.nanjo`）— expo.dev → Account Settings → Two-factor authentication
- [ ] **RevenueCat** — app.revenuecat.com → アカウント設定 → 2FA
- [ ] メール（`masaya.happylife@gmail.com` 等、上記の復旧に使うアドレス）にも2FA

### 2. パスワード衛生
- [ ] 上記アカウントは **すべて別々の強いパスワード**（使い回し厳禁）
- [ ] パスワードマネージャ（iCloudキーチェーン等）で管理
- [ ] 復旧用コード（2FAのバックアップコード）を安全な場所に保管

### 3. 端末・アクセス
- [ ] 開発に使う Mac / iPhone にパスコード・ロックを設定
- [ ] GitHub の不要な Personal Access Token / OAuth 連携を定期的に見直し・削除

## 🟡 継続的に守る

- **秘密情報を絶対にコミットしない。** APIシークレット・`.p8`・`.env` はコード/コミットに含めない（EAS の環境変数 or ダッシュボードで管理）。
- コミット前チェック（任意）：`git grep -nE "sk_[A-Za-z0-9]{16,}|BEGIN .*PRIVATE KEY|AIza[0-9A-Za-z_-]{20,}"` で秘密文字列が無いか確認。
- 依存パッケージは定期的に更新（`npm audit` の High は放置しない）。
- 通信は HTTPS のみ（iOS の ATS が既定で強制）。将来バックエンドを追加する場合も HTTP を使わない。
- RevenueCat の Webhook / API を追加する場合は、必ず署名検証を入れる。

## 🟠 コンテンツ盗用・AIクローン（Kimi K3 等）への対策

### 現実（正直に）
アプリに **同梱した文章は端末から抽出可能**（全アプリ共通）。AI は「抽出後の言い換え」を速くするだけで、同梱している限り技術的な完全防止は不可能。→ 「抑止」と「本命の技術対策」を分けて考える。

### 抑止（今できる）
- **Hermes バイトコード**（既に採用）＝ JS が多少難読化され、そのままの平文抽出はしにくい。
- **著作権表記・利用規約・特商法ページ**（既に実装）＝ 無断複製・再配布を禁止する法的抑止。
- ストア掲載文・規約に「問題・解説の複製/二次配布/スクレイピング禁止」を明記。

### 本命の技術対策（中期プロジェクト＝別途 B 案）
- **有料コンテンツのサーバー配信化**：有料問題を全部アプリに同梱せず、**購入確認後にサーバーから取得**。
  - 未購入者の端末に有料コンテンツが届かない
  - 一括ダウンロード（大量抽出）を検知・レート制限できる
  - ユーザー単位の透かし（識別子埋め込み）で流出元を追跡できる
- 実装には軽量バックエンド（例：サーバーレス関数＋DB）と、RevenueCat のエンタイトルメント検証連携が必要。事業が伸びて盗用が実害になった段階で着手が現実的。

### 戦略的な堀（最も効く）
生データより、**正確さ・更新頻度・図解の質・UX・ブランド**が模倣されにくい価値。丁寧な初心者向け図解や継続更新こそ、AI に丸コピーされにくい体験。

## インシデント時の初動（乗っ取り・漏洩を疑ったら）

1. 該当アカウントのパスワードを即変更＋2FA再設定、不審なセッション/トークンを失効。
2. RevenueCat / App Store Connect の直近アクティビティを確認。
3. 漏れた可能性のあるキーを **ローテーション**（新キー発行→旧キー無効化→EAS 環境変数更新→再ビルド）。
4. GitHub のアクセス履歴・デプロイキーを確認。
5. 影響範囲を記録し、必要なら再発防止をこのファイルに追記。
